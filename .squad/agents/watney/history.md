### RoslynRefactorTool (phase-4 transforms) — durable gotchas
- **dotnet:** use `~/.dotnet/dotnet` (net10.0 runtime), never the snap. Build: `~/.dotnet/dotnet build RoslynRefactorTool/RoslynRefactorTool.csproj -c Release -v quiet --nologo`. Dll: `RoslynRefactorTool/bin/Release/net10.0/RoslynRefactorTool.dll` (+ bundled `refs/`); Python resolves via `ROSLYN_REFACTOR_TOOL_DLL` (Release preferred, Debug fallback). csproj mirrors `Mode1Analyzer.csproj` (ref-pack fast-path, no per-project restore).
- Tool is PURE — JSON-only stdout (`{ok,applicable,reason,files{},seam{}}`), diagnostics to stderr; Python (`_invoke_roslyn_tool`) owns all writes, re-checks every path via `_safe_prod_path`, then `apply()` runs the behaviour-preservation build + auto-revert.
- **Extension forwarding** needs the static FQN form (`global::...LoggerExtensions.LogInformation(_inner, args)`) — the generated file has no `using`; instance members keep `_inner.M(...)`. Generated types use a `global::`-qualified `SymbolDisplayFormat`.
- **Generics:** reconstruct signatures from `IMethodSymbol.OriginalDefinition`, not the constructed bound symbol (else `T` gets substituted → CS0266). Call site keeps its explicit `<T>`.
- **parameterize delegator** must call the ENCLOSING method (`method.Identifier.Text`), not the seam member; the body rewriter uses the seam member name only to retarget the receiver.
- Inserted nodes carry no trivia — add explicit `ElasticCarriageReturnLineFeed` + 4-space `Whitespace` leading trivia; `ReplaceNode(old, IEnumerable<SyntaxNode>)` swaps one method for [delegator, overload]; only `.CSharp` is available (use node-level `NormalizeWhitespace()`, no `Formatter`).
- **`unbound_receiver` on a common BCL type** is almost certainly a missing-implicit-using, NOT a ref-identity problem. `BuildCompilation` skips `obj/` (where `*.GlobalUsings.g.cs` lives), so it prepends a synthetic `__ImplicitGlobalUsings.g.cs` with the SDK default set. Check `GetDiagnostics()` for `CS0246` first. Prefer the declared `this` param (`ReducedFrom.Parameters[0].Type`) for the receiver type.

### Analyzer-hardening for strict repos (TreatWarningsAsErrors + StyleCop + XML docs)
- Generated wrapper file must start `// <auto-generated/>` + `#nullable enable`.
- Injected members in the existing prod file: emit minimal `<param>`/`///` when siblings carry docs (+ `#pragma warning disable CS1591, CS1573` fallback); match the file newline + insertion-site indent; emit WITHOUT `?` if the effective nullable context is disabled. These fix CS1591/CS1573/SA1137/SA1505/CS8632 on jellyfin/aspnetcore/efcore/abp/orleans.

### Overload-candidate misselection (2026-06-12)
- **Root cause (orleans:0116):** `SeamCore.Locate` resolved the invocation via `GetSymbolInfo`; when overload resolution doesn't fully bind (`Symbol == null`, triggered by the net9-Abstractions vs net10-runtime reference-identity split on `ILogger`) it fell back to `CandidateSymbols.OfType<IMethodSymbol>().FirstOrDefault()` — an ARBITRARY overload. For `logger.LogDebug("msg", message, diag)` it grabbed the 4-param `LogDebug(EventId, Exception?, string?, params object?[])` instead of the reduced `LogDebug(string?, params object?[])`, so the wrapper exposed the wrong signature (CS7036/CS1503) → owning build failed (both transforms).
- **Subtlety:** the same blind `FirstOrDefault()` lived in `SameReceiverCallRewriter.VisitInvocationExpression`. Fixing only `Locate` made it WORSE — `BoundMethod` became correct while the site-matcher stayed wrong, so the `OverloadKey` comparison missed → `site_not_found` (0 rewrites). BOTH paths must resolve the overload identically.
- **Fix:** `SeamCore.PickBestCandidate(hit, candidates, model)` (public, reused by the rewriter) keeps only candidates whose extension-reduced param list is arity-compatible with the call (drop `this`, honor optional/`params`/generic arity), ranks by positional arg-type match (`ClassifyConversion`), exact fixed arity, then fewer params; falls back to first-candidate only when nothing is compatible (no regressions). Regression fixture `RoslynRefactorTool/tests/cases/overload_candidate_arity/`.
